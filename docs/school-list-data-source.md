# 학교 자동완성 데이터 소스

온보딩/프로필의 "학교 검색" 자동완성(`apps/mobile/src/data/schools.ts`)이 사용하는
전국 대학/전문대학 리스트를 최신 공식 데이터로 갱신하는 방법.

## 현재 상태

- `apps/mobile/src/data/schools.ts`: 공공데이터포털 API로 수집한 **442개교** 정적 목록
  (2026-08-09 기준, `scripts/fetch-schools.mjs`가 자동 생성 — 직접 수정 금지).
- `apps/mobile/scripts/fetch-schools.mjs`: 공공데이터포털 API를 1회 호출해 이 파일을
  재생성하는 스크립트.
- 매 요청마다 API를 호출하지 않는다 — 결과를 정적 TS 파일로 커밋해두고, 학교 개편/개명이
  있을 때(연 1~2회 정도)만 스크립트를 재실행하는 방식.
- 목록에 없는 학교는 자동완성 화면의 "직접 입력하기" 버튼으로 입력 가능 (안전망).

## 1. API 키 발급 방법

1. [공공데이터포털](https://www.data.go.kr) 회원가입 및 로그인.
2. 검색창에 **"전국대학및전문대학정보표준데이터"** 검색 →
   `https://www.data.go.kr/data/15107736/standard.do` 데이터셋 페이지로 이동.
3. 페이지 상단 **"활용신청"** 클릭.
   - 활용목적: 서비스 개발/모바일 앱 자동완성 등 자유 기술.
   - 계정 유형: **개발계정**으로 신청 (운영계정은 활용사례 등록 후 트래픽 상향 신청 별도).
4. 승인은 보통 자동 처리되며 짧으면 몇 분, 길어도 1~2시간 내 완료됨.
5. 승인 후 [마이페이지 > 오픈API > 활용신청 현황]에서 **일반 인증키(디코딩)** 값을 복사.
   - 인증키는 "인코딩"과 "디코딩" 두 가지가 제공되는데, 스크립트는 URL 파라미터를
     직접 조립하므로 **디코딩 키**를 사용해야 한다. 인코딩된 키(`%2B`, `%2F` 등이 포함된
     형태)를 받았다면 `decodeURIComponent()`로 한 번 디코딩해서 사용할 것.
6. 개발계정 트래픽 한도는 1,000건/일이지만, 전체 데이터가 약 2,000건(대학원 포함) 수준이라
   2페이지 호출로 충분히 갱신 가능.

## 2. 스크립트 실행

```bash
cd apps/mobile
SCHOOL_API_KEY=발급받은_디코딩_키 node scripts/fetch-schools.mjs
```

실제 응답 필드 검증 결과(2026-08-09), 이 API는 `{ header, body: { totalCount, items: { item: [...] } } }`
구조를 반환하며 주요 필드는 다음과 같음: `schlNm`(학교명), `mainbranchNm`(본교/분교 구분),
`univSeNm`(대학/전문대학/대학원 구분). 필드명이 이후 바뀌었다면
`SCHOOL_API_KEY=... node scripts/fetch-schools.mjs --inspect`로 첫 레코드를 찍어보고
`fetch-schools.mjs` 상단 상수를 맞춰 수정한다.

## 3. 데이터 정제 규칙 (스크립트가 자동 처리)

- **대학원 제외**: `univSeNm`이 "대학원"인 레코드(예: "OO대학교 OO대학원")는 제외하고
  학부 과정(대학/전문대학)만 남김. (1,995건 중 1,553건이 대학원이라 제외 없이는
  자동완성이 대학원 프로그램명으로 뒤덮임)
- **캠퍼스 표기는 `학교명(캠퍼스명)` 형식으로 통일**: 다중 캠퍼스 학교는 본교를 포함한
  모든 캠퍼스에 실제 캠퍼스명을 괄호로 붙인다 (예: "홍익대학교(서울캠퍼스)" /
  "홍익대학교(세종캠퍼스)", "가톨릭대학교(성심교정)" / "가톨릭대학교(성의교정)" /
  "가톨릭대학교(성신교정)"). 단일 캠퍼스 학교는 그대로 "학교명"만 표기.
  API는 캠퍼스를 "본교"/"제2캠퍼"/"제3캠퍼" 같은 일련번호로만 내려주고 실제
  이름을 제공하지 않으므로, 각 학교 주소(`lctnRoadNmAddr`)를 대조해 확인한 실제
  캠퍼스명을 `fetch-schools.mjs`의 `CAMPUS_NAME_OVERRIDES`에 수동으로 매핑해뒀다
  (2026-08-09 기준 20개 다중 캠퍼스 학교, 본교/분교 합쳐 43개 매핑). 새로 다중
  캠퍼스 학교가 늘어나면 이 표에 추가해야 함 — 없으면 "학교명(제2캠퍼스)"처럼
  일련번호 그대로 표시됨. "한국폴리텍 V 대학 순천캠퍼스"처럼 이름 자체에 캠퍼스가
  이미 붙어있는 경우는 "한국폴리텍 V 대학(순천캠퍼스)" 형태로 자동 재포맷.
- **원본 데이터 오타 보정**: 정부 표준데이터의 필드 길이 제한으로 캠퍼스명 끝 "스"가
  잘려 내려오는 경우가 있음(예: "제2캠퍼" → "제2캠퍼스", "…영남융합기술캠퍼" →
  "…영남융합기술캠퍼스"). 이런 잘린 표기를 감지해 보정.
- **폐교 필터링은 하지 않음**: 이 API는 폐교 여부 필드를 제공하지 않는다. Wikipedia
  등에서 수집한 폐교 후보 목록으로 자동 제외를 시도해봤으나, 국립강릉원주대학교·
  전남도립대학교처럼 **현재 실제 운영 중인 학교까지 잘못 걸러지는 오탐**이 나와서
  폐교 판별 자체를 포기함. 목록에 학교가 없어서 못 찾는 것보다, 이미 폐교된 학교가
  하나 더 보이는 쪽의 사용자 영향이 훨씬 작다고 판단(직접 입력 안전망도 있음).
- **정렬**: 가나다순 정렬 후 커밋.

## 4. 검토했지만 채택하지 않은 방법

- **실시간 API 호출**: 타이핑마다 네트워크 호출이 필요해 지연이 생기고, 개발계정
  트래픽 한도(1,000건/일)를 자동완성 트래픽이 쉽게 초과함. 오프라인 대응도 안 됨.
- **npm 패키지(`korea-universities` 등)**: 생성된 지 얼마 안 됐고(2026-01) star/fork 0,
  단일 유지보수자인 신생 패키지라 프로덕션 런타임 의존성으로 넣기엔 공급망 신뢰도가
  부족하다고 판단해 배제함. 이 API를 직접 호출해 정적 파일로 캐싱하는 방식이 결과물은
  비슷하면서 외부 패키지 의존이 없어 더 안전함.
